[cite_start]在《软件质量保证》实验报告中，**代码行度量 (Line of Code, LoC)** 是衡量软件规模最基本、最传统的度量指标 [cite: 460, 1493]。

根据你提供的实验指导书和 PPT 课件，代码行度量在本项目中的具体含义和要求可以从以下几个维度来理解：

### 1. 核心定义与度量对象
[cite_start]代码行度量主要用于量化软件的**规模 (Size)** [cite: 121, 460]。在面向对象程序设计的语境下，它不仅仅是简单的统计全文行数，还可以细化为：
* [cite_start]**类规模：** 统计整个类定义的总代码行数 [cite: 460]。
* [cite_start]**方法规模：** 统计类中各个具体方法的代码行数 [cite: 266, 460]。

### 2. 在实验项目中的地位
[cite_start]根据实验指导书的要求，代码行度量属于“传统度量点” [cite: 1470, 1493][cite_start]。虽然本次实验的核心是实现面向对象度量（如 CK 度量模型和 LK 度量模型），但代码行度量被作为**基础性指标**，要求集成到学生开发的“自动化软件度量工具”中 [cite: 1470, 1493]。

### 3. 实现方式建议
实验指导书为代码行度量的自动化实现提供了技术路径建议：
* [cite_start]**技术工具：** 对于 Java 程序，建议利用 Eclipse 中的 **ASTParser** [cite: 1470, 1497]。
* [cite_start]**实现原理：** 通过 ASTParser 获取程序的**抽象语法树 (AST)**，然后对语法树中的节点进行统计分析 [cite: 1470, 1497]。这种方式比简单的文本行数统计更精确，可以剔除注释、空行等干扰因素，更准确地反映逻辑规模。

### 4. 应用意义
代码行度量的结果在软件工程中具有多重用途，工具应支持利用这些数据进行：
* [cite_start]**预测与评估：** 辅助预测开发所需的工作量、成本以及开发时间 [cite: 1495, 1470]。
* [cite_start]**质量分析：** 如果一个类或方法的代码行数异常多（如 PPT 中提到的“上帝类”），可能意味着该模块职责过多，违背了“单一职责”原则，需要进行重构 [cite: 558, 1468]。
